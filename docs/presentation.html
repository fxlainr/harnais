Projet personnel · local-first

HARNAIS

Une mémoire qui m'appartient, que les IA consultent sans la posséder, et une boussole qui dit si mon usage de l'IA sert ce que je veux devenir.

A · Souveraineté et anti-bulleB · Boussole d'intentions

Version du 2026-10-17 · réalisé : phases 0 à 3, 36 tests verts · code : ~/dev/outils/harnais · cahier des charges : BRIEF.md

1 · Pourquoi

Plus l'IA me connaît, moins je la contrôle

Dépossession

La mémoire qui me décrit vit chez des fournisseurs, dans des formats que je ne lis pas.

Enfermement

La personnalisation renforce ce que j'étais au lieu de m'aider à évoluer : une chambre d'écho à une seule personne.

Dérive

L'usage glisse sans bruit : déléguer ce que je voulais apprendre, consommer au lieu de construire.

Le constat sur une mémoire Claude Code réelle, inventoriée le 2026-10-17

78fiches de mémoire écrites par Claude, dans 3 formats différents
0fiche relue ou validée par moi
27fiches rangées sous des dossiers déménagés, jamais rechargées
6+fiches qui pointent vers un dossier qui n'existe plus

Le même index, chargé dans toutes les sessions, mélange vie privée, informations RH marquées « ne pas diffuser » et montants clients. Une information clé n'était connue que d'une mémoire orpheline. Rien ne périme : un événement passé reste présenté comme à venir.

2 · Les deux harnais

Deux protections, une seule corde

Harnais A

Souveraineté et anti-bulle

Une mémoire maître sur ma machine. Des scopes disent quel outil lit quoi. Un audit mensuel mesure si la mémoire rétrécit les réponses. Une mémoire ancienne peut être « graduée » : conservée, mais plus injectée.

Harnais B

Boussole d'intentions

Une charte de valeurs et d'intentions, écrite par entretien. Chaque session IA est rattachée à une intention. Un rapport hebdomadaire montre l'écart entre l'usage réel et les priorités déclarées.

3 · Architecture

Le coffre au centre, les IA en périphérie

Les fichiers du coffre sont la seule source de vérité. Les IA n'y accèdent que par une passerelle qui applique les scopes. Les agents lisent le coffre et n'y écrivent que des propositions. Le contenu des sessions est lu par un modèle local : il ne quitte jamais la machine.

Pile technique

Python 3.12 géré par uv, CLI typer, SDK officiel mcp 2.3 (MCPServer, transport stdio), python-frontmatter, sqlite3 de la bibliothèque standard, pytest. Pas de framework d'agents : des modules Python simples et des sous-agents Claude Code. Le modèle se choisit par agent derrière harnais/llm.py : LM Studio, Anthropic ou Ollama.

Tout est un fichier que je peux lire

│   ├── intentions/        # une carte par intention
│   └── a-garder-pour-moi.md

Trois types de mémoire

Ajoutés après l'inventaire du 2026-10-17, qui montrait trois natures mélangées.

TypeExemple
faitChez ce client, l'instance de décision est le COPIL.
consigneDimensionner l'effort à la demande. Ne décroît pas sans accord.
pointeurL'état du chantier est dans chantier.md de son dossier.

Chaque mémoire porte un poids, un scope, une date valable_jusqu_au et un drapeau gradue. Le journal ne garde jamais le transcript : un résumé de 3 à 5 lignes et des métadonnées.

Qui lit quoi : le dossier de travail décide

Tu travailles dansContexteClaude Code litDonnées sensibles
Un dossier perso (vacances, maison)persoperso, famille, santé, relations, financesoui, ce contexte les nomme

Ailleursdéfautpro, apprentissage, créationjamais

Pour une exception, je tape /contexte perso : le contexte s'ouvre pour la session en cours et se referme seul à sa fin. Chaque ouverture et chaque lecture de données personnelles figure dans le rapport hebdomadaire.

Le but est la pertinence, pas le cloisonnement. Parmi les mémoires autorisées, la passerelle sert d'abord ce qui concerne le projet du dossier, puis mes consignes, puis ce qui touche l'intention du projet ou le sujet demandé, et dit pourquoi chaque mémoire a été servie. Le rapport hebdomadaire mesure aussi l'ouverture : part des sessions concentrées sur trois sujets, sujets nouveaux, et rappel de l'audit de bulle et du contradicteur.

5 · Déploiement sur Claude

Quatre points de branchement, tous sur ma machine

Rien n'est hébergé. Le code vit dans ~/dev/outils/harnais, le coffre dans ~/harnais-coffre, la clé API dans un .env ignoré par Git. Une seule commande installe tout, et demande mon accord avant chaque branchement :

cd ~/dev/outils/harnais && ./scripts/installer.sh
1 · Passerelle MCP

Claude Code lance le serveur à la demande, en local, par stdio. Le client est fixé ici, pas par l'IA.

claude mcp add harnais -s user \
  -e HARNAIS_CLIENT=claude_code -- \
  ~/dev/outils/harnais/.venv/bin/python \
  -m harnais.mcp_server
2 · Hook de fin de session

Claude Code accorde 1,5 s à ses hooks de fin de session : celui-ci se contente de mettre la session en file, sans appel modèle. Il ne fait jamais échouer Claude Code.

"SessionEnd": [{ "hooks": [{
  "type": "command",
  "command": "…/.venv/bin/python
    -m harnais.hooks.session_end" }]}]
3 · Taggage asynchrone

Un agent launchd lance harnais tagger toutes les heures. Il démarre LM Studio si besoin, charge le modèle, vide la file, puis libère la mémoire. Une session en échec reste en file.

4 · Commandes et sous-agent

/charte, /revue-hebdo, /audit-bulle, /revue-trimestrielle, disponibles dans tous les projets par lien symbolique. /charte mène l'entretien dans la conversation : une question à la fois, à partir de situations vécues, chaque carte relue avant écriture.

claude.ai n'a pas d'accès direct : un serveur stdio local ne lui est pas joignable. Il entre par l'import de son export de données (phase 2). Un accès en direct demanderait d'exposer la passerelle, ce qui contredit le local-first : voir les points ouverts.

7 · Rituels

Une seule action par semaine, moins de 5 minutes

Tout ce qui demande un effort quotidien finit abandonné. La collecte est automatique ; je n'interviens qu'aux rendez-vous ci-dessous.

Chaque session

Collecte

Le hook met la session en file ; le tagueur local écrit la fiche dans l'heure. Je ne fais rien.

0 min
Chaque semaine

/revue-hebdo

Je lis le rapport du gardien, consommation de tokens comprise, et je valide en lot tags et propositions de mémoire.

< 5 min
Chaque mois

/audit-bulle

Après confirmation du coût, l'auditeur mesure l'effet de ma mémoire sur les réponses. Le contradicteur peut suivre.

≈ 15 min
Chaque trimestre

/revue-trimestrielle

Pour chaque intention : dérive à corriger, ou évolution à acter ? Les cartes changent, Git garde l'historique.

≈ 30 min
Au départ, puis chaque trimestre

/charte

Entretien de valeurs : 4 à 6 valeurs, 5 à 10 intentions, la liste de ce que je garde pour moi.

≈ 45 min

9 · Principes

Ce qui n'est pas négociable

  • Local-first. Tout tourne sur ma machine, aucune synchronisation cloud par défaut.
  • Fichiers ouverts. Markdown et YAML ; l'index se reconstruit depuis les fichiers.
  • L'humain tranche. Les agents proposent, je valide. Rien n'entre dans memoire/ sans moi.
  • Indicateurs, pas notes. Aucun score global d'alignement : il deviendrait la cible.
  • Dérive ou évolution. Toute alerte propose les deux lectures : revenir à l'intention ou la faire évoluer.
  • Moins on stocke, mieux c'est. Résumés plutôt que transcripts, métadonnées plutôt que contenu.
  • Modèle interchangeable. API Anthropic ou modèle local via Ollama, selon la configuration.
  • Aucun secret dans le coffre. Les clés vivent dans un .env hors Git.

11 · Points ouverts

À trancher à l'usage

Accès de claude.ai

Import d'export seulement (local-first strict), ou passerelle exposée sur le réseau avec authentification ? Le scope claude_ai ne sert rien en direct aujourd'hui. Le format de l'export reste à vérifier sur un vrai fichier (--inspecter).

Sort de la mémoire Claude actuelle

Une fois les 67 propositions triées, faut-il vider les fiches de ~/.claude et laisser HARNAIS seul maître, ou garder les consignes en double ?

Confiance du tagueur

Les modèles locaux déclarent presque toujours 0,9 à 0,95. Toute session sans intention part donc en revue ; la règle sera recalibrée après quelques semaines.

Référence de l'auditeur de bulle

Le papier « The Echo Chamber of One » (NeurIPS 2026) n'a pas été vérifié. La méthode tient sans lui ; la citation est à confirmer avant tout partage.
